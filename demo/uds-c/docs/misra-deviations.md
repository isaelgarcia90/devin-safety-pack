# MISRA C:2012 deviation records

Checked with cppcheck 2.7 (`--addon=misra`), invoked as `tools/safety_gate.py` does: on `src/`, without include paths.
The gate accepts a deviation per rule, so each row below lists every location it covers.

| Rule | Justification | Risk | Mitigation |
|---|---|---|---|
| misra-c2012-8.4 | 13 findings on every external function in `uds.c` and `extras.c`. Each one has a compatible prototype in `uds/uds.h` / `uds/extras.h`, included first by the `.c` file. cppcheck reports 8.4 because the gate runs without `-I`, so it cannot open those headers. With `-Isrc -Ideps/isotp-c/src -Ideps/isotp-c/deps/bitfield-c/src` the findings go away. Tool artifact. | Low: a prototype that disagrees with its definition would not be caught by this check. | `-Wall -Werror` build of every translation unit against the same headers. A reviewer should rerun cppcheck with include paths. |
| misra-c2012-14.4 | 4 findings: `if(handle->request.has_pid)` (`send_diagnostic_request`), `if(message.completed)` (`diagnostic_receive_can_frame`) and `if(x->has_pid)` in `diagnostic_response_to_string` / `diagnostic_request_to_string`. Each operand is declared `bool` (`<stdbool.h>`), so the controlling expression is already essentially Boolean. cppcheck cannot see the type without include paths. These findings also go away with `-I`. Tool artifact. | Low. | Types are fixed in `uds_types.h` / `isotp_types.h`, and the build is `-Werror`. |
| misra-c2012-2.2 | 2 findings on `PID_BYTE_INDEX * CHAR_BIT` (`send_diagnostic_request`, `handle_positive_response`). `PID_BYTE_INDEX` is 1, so cppcheck treats the multiplication as redundant. It states the byte-to-bit offset of the PID and is kept for readability. It is not dead code. | None: the result is identical. | Covered by `test_request_pid_enhanced` and `test_autoset_pid_length`. |
| misra-c2012-15.4 | 1 finding: the receive loop in `diagnostic_receive_can_frame` (REQ-006/REQ-008, ASIL B/C) has two `break` statements, one for a completed message and one for a partial multi-frame. A single exit needs a restructured loop and changes the ISO-TP (ISO 15765-2 transport layer) receive control flow. That rewrite is not mechanical. | Medium: the loop is hard to reason about, and the multi-frame path is already non-compliant with REQ-008 (finding F-01). | Not fixed on purpose. Restructure it with the REQ-008 fix, with tests for the multi-frame flow. |
| misra-c2012-2.7 | 10 findings on unused parameters in `extras.c` (`diagnostic_request_malfunction_indicator_status`, `diagnostic_request_vin`, `diagnostic_request_dtc`, `diagnostic_clear_dtc`, `diagnostic_enumerate_pids`). These are upstream placeholders ("future work") and no requirement covers them. By AGENTS.md rule 1 they are not modified without a requirement. (The 2 findings in `uds.c` were fixed.) | Low as long as nobody calls them. They return empty handles / `false`. | Finding F-04. Integrators must not call these APIs. Add requirements before implementing them. |
| misra-c2012-10.4 | 5 findings in `diagnostic_response_to_string` / `diagnostic_request_to_string`: `size_t - int` in `snprintf` length arguments. No requirement covers these log formatters, so they are not modified (AGENTS.md rule 1). | Low: diagnostic logging only. A negative `bytes_used` could wrap the length. | Called only through the optional log shim with 128-byte buffers. Fix when a logging requirement exists. |
| misra-c2012-18.4 | 3 findings: `destination + bytes_used` pointer arithmetic in the same `*_to_string` formatters (no requirement). | Low: logging only. | Same as 10.4. |
| misra-c2012-10.3 | 1 finding: `int remaining_space = destination_length - bytes_used;` in `diagnostic_request_to_string` (no requirement). | Low: logging only. | Same as 10.4. |
| misra-c2012-17.7 | 2 findings: ignored `snprintf` return values in `diagnostic_request_to_string` (no requirement). The 3 `memcpy` findings in functions that have a requirement were fixed with `(void)`. | Low: truncated log text. | Same as 10.4. |
